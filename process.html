From a question
to a working product.

How I built Navigator AI through research, iteration, and a lot of debugging.

I began by researching how AI systems can answer questions using information that is specific to an organization. The main idea I studied was retrieval-augmented generation, or RAG. In a RAG system, the assistant first searches a collection of relevant documents and then generates an answer using the information it retrieved. This mattered for Navigator because school questions need to be grounded in the actual communications, policies, and updates that users have access to, rather than answered from broad general knowledge.

After that, I built the core pipeline. Navigator ingests school-related information from ParentSquare communications received through email and processes it using the Gemini API. The system organizes posts, extracts useful details, and makes the content searchable so users can ask questions naturally. I also worked on extracting structured information such as events, deadlines, links, and key people, because those details could later support recent updates, suggested questions, and more precise answers. The product was built as a web application using Next.js and TypeScript, with a database to store users, posts, chats, projects, citations, source metadata, and settings.

One of my biggest design inspirations was NotebookLM. I liked how it makes sources part of the reading experience rather than something separate from the answer. I wanted Navigator to have a similar source-grounded structure: answers include citation markers in the response, and when users click a citation, the original source can open in a sidebar. This made citations a central part of how Navigator builds trust.

The backend was one of the most difficult parts of the project. Early versions had problems that only became obvious once the app became more realistic. Citations did not always persist after reloading old chats, suggested questions sometimes surfaced outdated events, chat titles were not always generated, and different parts of the app did not always use the same source logic. I worked through these issues by revising how messages, source metadata, user-specific information, and recent updates were stored and retrieved.

I also incorporated feedback from Laura during testing. One important issue she noticed was recency: Navigator sometimes surfaced older events when users asked current questions like "What's happening this week?" Fixing this required adjusting the retrieval logic so recent and upcoming information was prioritized more carefully. Combined with the teacher and staff survey feedback, this helped me understand that useful AI depends on the whole system around the model: the sources, interface, retrieval logic, citations, feedback loops, and the trust users need before they rely on it.
